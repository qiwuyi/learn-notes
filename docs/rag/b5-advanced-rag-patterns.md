# 高级 RAG 模式

进阶专题 B5

::: tip 本专题定位
前面学的都是**朴素 RAG（Naive RAG）**：一次检索、一次生成。这一课介绍几个 RAG 生态里的进阶范式——
它们解决朴素 RAG 的什么问题、核心思路是什么、什么时候值得用。**知道"有这些模式、各自解决什么"比记住实现更重要。**
:::

## 回顾：朴素 RAG 的局限

本仓库就是一个标准朴素 RAG：

```text
问题 ──▶ 向量化 ──▶ 检索 topK ──▶ 拼提示词 ──▶ 生成
```

它的软肋：
- **检索一次定生死**：第一轮检索不好，后面全白搭
- **不知道什么时候该检索**：问"你是谁"也去检索一遍，浪费且引入噪声
- **跨多文档推理弱**：答案分散在多个来源时，一次性检索难凑齐
- **上下文超限**：检索太多塞不下

## 模式 1：Self-RAG（自我反思式 RAG）

**核心**：让 LLM 在生成过程中自己判断——"该不该检索？检索到的够不够？回答可不可信？"

```text
问题 ──▶ LLM 判断：需要检索吗？
          ├─ 不需要 → 直接回答（如"你好"）
          └─ 需要 → 检索 → LLM 检查检索结果是否相关
                      ├─ 相关 → 基于它回答
                      └─ 不相关 → 重新检索 / 换关键词
回答时还生成"自评 token"：这段有依据吗？有帮助吗？
```

**解决**：盲目检索、检索质量无人把关。

## 模式 2：Corrective RAG（纠正式 RAG，CRAG）

**核心**：先检索，再**评估检索结果质量**，质量差就"纠正"——重写查询或扩大检索。

```text
问题 ──▶ 检索 ──▶ 评估器给检索结果打分
          ├─ 高质量 → 直接用
          ├─ 中质量 → 部分保留 + 补充
          └─ 低质量 → 重写查询再检索 / 用网络搜索兜底
```

**解决**：检索质量不稳定时的兜底。

## 模式 3：GraphRAG（图谱 RAG）

**核心**：不只存"文本向量"，还把文档抽成**实体和关系图谱**（知识图谱），支持跨实体推理和多跳问答。

```text
朴素 RAG：  检索到 3 段文本 ──▶ 拼给 LLM
GraphRAG：  抽取实体+关系（A 依赖 B、B 属于 C）
           ──▶ 沿图谱走多跳：A→B→C 找到完整链条
```

**解决**：多跳推理、全局性问题（"公司所有产品的关系"）——朴素 RAG 很难回答"全局"问题。
代价：构建图谱成本高。

## 模式 4：Agentic RAG（智能体 RAG）

**核心**：把检索交给**智能体（Agent）**编排——它可以多次检索、调用工具、规划步骤，像"会用检索工具的人"。

```text
Agent 循环：
  1. 拆解问题（可能需要多个子查询）
  2. 调用检索工具（不同知识库 / 数据库 / 搜索）
  3. 看结果，决定：够了？还是要再查？
  4. 多轮直到信息足够，再综合回答
```

**解决**：复杂问题、跨多个数据源、需要多步推理的场景。
代价：延迟高、不可控、要防 Agent 跑偏。

## 一张图对比

| 模式 | 一句话 | 解决什么 | 代价 | 适合 |
| ---- | ------ | -------- | ---- | ---- |
| **朴素 RAG** | 一次检索一次生成 | 基础问答 | 无 | 简单知识库（本仓库） |
| **Self-RAG** | 边生成边反思"要不要查、够不够" | 盲目检索 | 慢 | 对幻觉敏感 |
| **CRAG** | 检索后评估，差就纠正 | 检索不稳 | 多一步评估 | 数据质量参差 |
| **GraphRAG** | 文档→实体图谱，多跳推理 | 全局/多跳问答 | 建图贵 | 需要全局关联 |
| **Agentic RAG** | Agent 编排多轮检索+工具 | 复杂多源问题 | 慢、不可控 | 复杂任务 |

## 什么时候升级？

**先确认朴素 RAG 真的不够用**：

1. 指标（B4）显示检索召回差 → 先试 B3（Hybrid/Rerank），别急着上高级模式
2. 用户常问**全局/关系型**问题 → 考虑 GraphRAG
3. 问题**需要多步推理/多源** → 考虑 Agentic RAG
4. **幻觉敏感**（金融、医疗）→ 考虑 Self-RAG 的自评机制

::: warning 升级建议
高级模式不是免费的：延迟、成本、复杂度都涨。**从朴素 RAG 起步（本仓库就是这样），用指标（B4）驱动升级**，是工程上最稳的路径。
:::

## 自测

::: details 测验 · 点击展开

**1. 朴素 RAG 最大的局限是？**
- ❌ 成本太高（它最便宜）
- ✅ **检索一次定生死，且不知道什么时候该检索**
- ❌ 无法部署
- ❌ 不需要向量库

**2. Self-RAG 的核心思想是？**
- ❌ 只检索不生成
- ✅ **生成过程中自我判断"要不要检索、检索够不够"**
- ❌ 永远不检索
- ❌ 用图谱代替检索

**3. CRAG（纠正式 RAG）的特色是？**
- ❌ 完全不检索
- ✅ **检索后评估质量，差就重写查询/兜底**
- ❌ 只用 BM25
- ❌ 一次检索就完事

**4. GraphRAG 相比朴素 RAG 的核心差异是？**
- ❌ 用更大的 embedding 模型
- ✅ **抽取实体关系成图谱，支持跨实体多跳推理**
- ❌ 不需要向量库
- ❌ 更快更便宜（它更贵）

**5. 工程上最稳的升级路径是？**
- ❌ 直接上最贵的 Agentic RAG
- ✅ **从朴素 RAG 起步，用指标（B4）驱动，先试 Hybrid/Rerank（B3）再考虑高级模式**
- ❌ 永远不升级
- ❌ 只看演示效果

:::

## 小结

- 朴素 RAG 一次检索一次生成，简单但"一次定生死"
- 高级模式各有专攻：**Self-RAG**（反思）、**CRAG**（纠正）、**GraphRAG**（图谱多跳）、**Agentic RAG**（智能体编排）
- 用 B4 指标驱动升级，先低成本方案（B3）再高级模式
