# 从语言模型到 RAG

AI 基础专题第五课 · 打通 AI 基础 → RAG → Pi 的串联课

::: tip 本课目标
这是三个专题的"合龙"课：AI 基础讲了模型原理（③④），RAG 讲了怎么用模型检索，
Pi 讲了怎么把模型封装成系统。这一课把"语言模型 → LLM → RAG"的完整链条串起来。
:::

## 语言模型是什么

**语言模型 = 预测下一个词的概率机器**：

```text
P(w_N | w_0, ..., w_{N-1})

输入: "今天天气真"
输出: P("好"|...) = 0.6, P("差"|...) = 0.2, P("的"|...) = 0.1, ...
```

第 ④ 课学的 GPT 就是大规模训练这个任务：海量文本里学会"词与词的搭配规律"。

**关键洞察（GPT-2 论文）**：*"理解文本本质上就是能生成文本"*——会预测下一个词的模型，被迫学会了语法、常识、甚至推理（不然预测不准）。

## 衡量语言模型：困惑度（Perplexity）

怎么不靠具体任务衡量语言模型质量？**Perplexity（困惑度）**：

```text
直觉：模型对"正确答案"有多确定
模型给正确的下一词概率越高 → 困惑度越低 → 模型越好

例子：句子 "我早饭吃了面包"
模型 A 预测 "面包" 概率 0.5 → 困惑度低（好）
模型 B 预测 "面包" 概率 0.001 → 困惑度高（差）
```

它是"内在指标"（不需要标注数据），是预训练阶段的指挥棒。

## 预训练 → 涌现能力

GPT 路线的革命（微软课引用的 GPT-2 论文）：

```text
传统路线：训练一个模型解决一个任务（分类要标数据、翻译要标数据…）
GPT 路线：  海量文本预训练"预测下一个词"
           → 模型自动具备多种能力（翻译/摘要/问答…）
           → 零样本（zero-shot）：不给例子也能做
           → 上下文学习（in-context learning）：给几个例子就能做
```

这就是"涌现"——能力不是单独教的，是"预测下一个词"这件事**顺带**学会的。

## LLM 的局限（为什么需要 RAG）

LLM 很强，但有天生短板（RAG 专题第一课的"核心问题"的理论根源）：

| 短板 | 原因 | RAG 的解法 |
| ---- | ---- | ---------- |
| 知识过时 | 训练数据有截止日期 | 检索**最新**文档 |
| 不知道私有知识 | 没见过你的内部文档 | 检索你的知识库 |
| 幻觉 | 预测下一个词时"编" | 约束它基于检索内容回答 |
| 无出处 | 生成过程不可溯源 | 返回真实来源 |

**一句话**：LLM 是"训练时知道的"，RAG 让它"提问时现查"——知识从**参数记忆**扩展到**外部检索**。

## 完整链条（三专题合龙）

```text
AI 基础专题                        RAG 专题                Pi 专题
─────────────                    ─────────               ─────────
② 神经网络（训练原理）                │                      │
③ Embeddings（向量语义）──────▶ B2 选 embedding 模型       │
④ Transformer（模型底座）           │                      │
⑤ 语言模型（GPT 原理）───────▶ LLM 生成回答          ② 统一调 LLM
                              检索（B1 chunking）────▶ ③ agent loop 封装
                              评估（B4）                  │
                                                       ⑦ RAG-as-Tool
```

**每条线的角色**：
- **AI 基础**：回答"模型怎么工作"（原理）
- **RAG**：回答"怎么让模型用上知识"（模式）
- **Pi**：回答"怎么把模型+知识封装成产品"（工程）

## 一个完整认知闭环

现在你拥有一个从底层到应用的完整链条：

```text
问："为什么 RAG 能让聊天机器人回答我博客的内容？"

AI 基础视角：LLM 是预测下一个词的模型，它的知识在训练时定死
RAG 视角：  把你的博客切成 chunk → 向量化 → 提问时检索 → 塞进提示词
Pi 视角：   把这些能力封装成工具，让 agent 自主调用
```

三个视角叠加 = 完整理解。这是本站 19 篇课程（AI 5 + RAG 9 + Pi 7 部分重合）真正想给的收获。

## 自测

::: details 测验 · 点击展开

**1. 语言模型的本质任务是？**
- ✅ **预测下一个词（P(w_N | 前面的词)）**
- ❌ 翻译文本
- ❌ 分类图片
- ❌ 生成随机文本

**2. Perplexity（困惑度）衡量什么？**
- ✅ **模型对"正确的下一个词"有多确定（越低越好）**
- ❌ 模型大小
- ❌ 训练速度
- ❌ 词汇量

**3. GPT 路线的核心发现是？**
- ✅ **大规模"预测下一个词"的模型自动具备多种能力（涌现）**
- ❌ 每个任务必须单独训练
- ❌ 模型越大越差
- ❌ 预训练无用

**4. LLM 幻觉的根源是？**
- ✅ **生成是"预测下一个词"，没有事实约束时会"编"**
- ❌ 训练数据太多
- ❌ 模型太小
- ❌ 网络问题

**5. RAG 解决 LLM 哪个短板最直接？**
- ✅ **知识过时/私有知识不可知——用检索把外部知识塞进提示词**
- ❌ 模型速度
- ❌ 模型成本
- ❌ 模型大小

:::

## 小结

- 语言模型 = 预测下一个词；困惑度是它的内在质量指标
- GPT 路线：预训练 → 涌现能力（零样本/上下文学习）
- LLM 短板（过时/私有/幻觉）→ **RAG 用检索补**
- 三专题合龙：**原理（AI）→ 模式（RAG）→ 工程（Pi）**
