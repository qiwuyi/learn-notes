# Embeddings 深度理解

AI 基础专题第三课 · 基于微软课程第 14 课

::: tip 本课目标
RAG 专题的 B2 学了"怎么选 embedding 模型"，这一课补上**原理**：词是怎么变成向量的、
Word2Vec 怎么训练、为什么"语义相近 → 向量相近"。两课合起来才是完整的 Embedding 认知。
:::

## 从 one-hot 到稠密向量

最早表示"词"的方式是 **one-hot**（独热编码）：

```text
词表: [猫, 狗, 跑, 吃]
"猫" = [1, 0, 0, 0]
"狗" = [0, 1, 0, 0]
"跑" = [0, 0, 1, 0]
```

两个致命问题（微软课里讲得很直接）：
1. **内存爆炸**：词表多大向量就多大（几万词 = 几万维，且几乎全是 0）
2. **无语义**：one-hot 里"猫"和"狗"的距离 = "猫"和"跑"的距离——完全一样，表达不了"猫狗相近"

**Embedding 的思路**：用**低维稠密向量**表示词，且让**语义相近的词向量相近**：

```text
"猫" = [0.2, -0.8, 0.5]     ← 距离近
"狗" = [0.3, -0.7, 0.4]     （语义相近）

"跑" = [0.9, 0.1, -0.3]     ← 距离远（语义不同）
```

## Word2Vec：让向量学到语义

怎么让向量"自动"带上语义？**Word2Vec**（Mikolov et al., 2013）的答案：**从上下文学**——"一个词的含义由它周围的词定义"（分布假说）。

两种训练架构：

```text
① CBOW（Continuous Bag-of-Words）
   输入：上下文词（前后的词）
   输出：预测中间的词
   例：给 [我, 养, 一只, 猫] 里的 [我,养,一只]，预测 "猫"
   → 快，适合大语料

② Skip-gram
   输入：中心词
   输出：预测上下文
   例：给 "猫"，预测它周围可能出现 [我,养,一只]
   → 慢但低频词表现更好
```

训练副产品就是我们要的：**网络中间的隐藏层权重 = 词向量**。

## 著名的"语义算术"

Word2Vec 火了之后，人们发现向量能做**语义运算**：

```text
国王 - 男人 + 女人 ≈ 女王
King  - man  + woman ≈ Queen

巴黎 - 法国 + 意大利 ≈ 罗马
```

**原因**：训练时"国王"和"女王"总出现在相似上下文里（君主语境），它们的向量差异主要编码了"性别"这个维度。向量的方向承载了语义特征。

## 局限：一词多义

Word2Vec 有个硬伤——**每个词只有一个向量**，但词有多个意思：

```text
I went to a play at the theatre.     play = 戏剧
John wants to play with friends.     play = 玩耍
```

Word2Vec 把两种意思**平均**进同一个向量。微软课指出解法：**上下文嵌入（Contextual Embeddings）**——基于语言模型的嵌入，同一个词在不同上下文里向量不同（这正是 Transformer/BERT 干的事，第 ④ 课展开）。

## Embedding 的演进全景

```text
one-hot ──▶ Word2Vec/GloVe ──▶ 上下文嵌入（BERT/GPT）──▶ 现代 Embedding 模型
 (无语义)    (静态词向量)       (一词多义)             (句子级、多语言)
                                                  ↑
                                          RAG 专题 B2 讲的
                                          bge/gte/Qwen embedding
```

关键跃迁：
1. **one-hot → Word2Vec**：维度降下来 + 有语义
2. **Word2Vec → 上下文嵌入**：解决一词多义
3. **词向量 → 句子/段落向量**：RAG 需要的是 chunk 级的向量（整段语义），现代 embedding 模型（B2 学的）就是干这个

## 回到 RAG 专题

现在你明白 B2 为什么那样选了：

| B2 的概念 | 本课的原理基础 |
| --------- | ------------- |
| "embedding 模型" | Word2Vec 等训练出的向量表示 |
| "语义相近 → 距离近" | 分布假说 + Word2Vec 训练目标 |
| "MTEB 评测 Retrieval" | 衡量"查询和文档向量是否语义对应" |
| "中文效果" | 词法/语境差异，需中文语料训练 |

**一句话总结**：B2 是"消费者视角"（选哪个模型），本课是"生产者视角"（模型怎么造出来）。

## 自测

::: details 测验 · 点击展开

**1. one-hot 的两个致命问题是？**
- ✅ **内存爆炸 + 无语义（词与词距离都一样）**
- ❌ 太慢 + 太难写
- ❌ 太长 + 太短
- ❌ 没有这两个问题

**2. Word2Vec 训练的依据是？**
- ✅ **分布假说：词的含义由上下文定义（从上下文预测词）**
- ❌ 人工标注词典
- ❌ 词的拼写规则
- ❌ 随机初始化就够了

**3. Skip-gram 和 CBOW 的区别是？**
- ✅ **CBOW 从上下文预测中心词（快）；Skip-gram 从中心词预测上下文（慢但低频词好）**
- ❌ 完全一样
- ❌ Skip-gram 更快
- ❌ CBOW 不需要训练

**4. "国王 - 男人 + 女人 ≈ 女王"说明什么？**
- ✅ **向量方向承载语义特征（如性别维度）**
- ❌ 向量是随机的
- ❌ 数学算错了
- ❌ 只是巧合

**5. Word2Vec 解决不了一词多义，怎么办？**
- ✅ **上下文嵌入：同一个词在不同语境向量不同（Transformer/BERT）**
- ❌ 没有解决办法
- ❌ 用更长的向量
- ❌ 把词拆成字母

:::

## 小结

- one-hot（无语义）→ **Word2Vec**（从上下文学语义）→ 上下文嵌入（一词多义）
- Word2Vec 两种架构：CBOW / Skip-gram，训练副产品就是词向量
- 向量能"语义算术"（king - man + woman ≈ queen）
- RAG 的 embedding 选型（B2）建立在本课原理之上
